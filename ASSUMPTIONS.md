# Assumptions

These assumptions were made while generating the repository-operating blueprint pack for a greenfield implementation.

| ID    | Assumption                                                                                                                                                     | Reason                                                                                                                          | Risk if Wrong                                                                              | How to Verify                                                                                   | Blocks Implementation                                                |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A-001 | The repository is greenfield and may initially contain only this blueprint pack.                                                                               | The selected status is "Greenfield repository."                                                                                 | Scripts that expect application files may fail until EP-001 creates the monorepo skeleton. | Run `find . -maxdepth 3 -type f                                                                 | sort`and compare with`EP-000` discovery notes.                       | No. EP-001 handles foundation creation. |
| A-002 | The default implementation uses a TypeScript monorepo with `pnpm`, Next.js, NestJS, shared packages, and separate Python/Go/Rust services added progressively. | The preferred stack recommends Next.js, React, TypeScript, NestJS/FastAPI, Python AI orchestration, optional Go, optional Rust. | A different stack would make some command names and directories stale.                     | Inspect `package.json`, `pnpm-workspace.yaml`, service directories, and CI files during EP-000. | No, unless an existing repo conflicts materially.                    |
| A-003 | PostgreSQL with PostGIS is the authoritative data store.                                                                                                       | Requirements explicitly state PostgreSQL system of record and PostGIS geospatial search.                                        | Schema and repository plans would need adjustment for another database.                    | Check `docker-compose`, migrations, ORM config, and architecture decisions.                     | Yes for persistence implementation if changed.                       |
| A-004 | OpenSearch or Elasticsearch is used for property/lead/list search projections, not as source of truth.                                                         | Requirements call for nationwide-scale search and raw data as authoritative.                                                    | Search implementation could incorrectly overwrite canonical records.                       | Inspect persistence specs, indexing workers, and tests for projection behavior.                 | No for Phase 1; yes for search-heavy features.                       |
| A-005 | Redis is available for local development through Compose after EP-003.                                                                                         | Requirements list Redis for caching, queues, sessions, rate limits, and ephemeral state.                                        | Workers, queues, rate limits, and cache tests may need alternative adapters.               | Run `docker compose ps redis` once Compose files exist.                                         | No for pure domain work; yes for queue/cache integration.            |
| A-006 | Object storage uses local filesystem in budget mode and MinIO/S3-compatible storage in production profiles.                                                    | Requirements call for local/S3-compatible storage and MinIO optional.                                                           | Artifact persistence adapters may need provider-specific differences.                      | Verify `OBJECT_STORAGE_PROVIDER` and storage adapter tests.                                     | No.                                                                  |
| A-007 | Built-in auth is the initial budget/default auth mode, with Keycloak/authentik and commercial SSO as adapters later.                                           | Requirements recommend built-in auth plus self-hosted SSO and premium options.                                                  | Initial RBAC/session design may need refactor if external IdP is mandatory from day one.   | Review `SPEC-005` and tenant deployment profile.                                                | No.                                                                  |
| A-008 | Investor/acquisitions workflows are default and licensed-agent/brokerage workflows are optional.                                                               | Product owner is assumed not licensed and special instructions require investor-first defaults.                                 | UI copy, permissions, and compliance flows could be wrong if product pivots to agent-only. | Confirm product mode settings and onboarding defaults.                                          | Yes if contradicted by a later user instruction.                     |
| A-009 | PropStream is a category benchmark only and must not be copied.                                                                                                | Business constraints prohibit cloning or protected expression reuse.                                                            | Legal and product risk.                                                                    | Review feature names, UI copy, docs, and design provenance before release.                      | Yes if a requested change asks to copy proprietary content.          |
| A-010 | Cobras Real Estate CRM is reference-only unless licensing/provenance is approved later.                                                                        | Business constraints require formal code reuse decision.                                                                        | License contamination or provenance risk.                                                  | Confirm a license review ADR before importing/copying code.                                     | Yes for direct code reuse.                                           |
| A-011 | National DNC is suppression/compliance data only, not lead-generation data.                                                                                    | Security/compliance constraints state this explicitly.                                                                          | Severe legal/compliance risk.                                                              | Search code/docs for DNC import and UI exposure paths.                                          | Yes if violated.                                                     |
| A-012 | Outbound calling and AI voice campaigns are blocked by default until compliance evidence exists.                                                               | Requirements require cold outbound calling/AI voice locked when prerequisites are missing.                                      | Compliance exposure and user harm.                                                         | Run compliance gate tests for missing consent/DNC credentials.                                  | Yes for voice/call campaign launch.                                  |
| A-013 | DeepSeek is optional and must be behind an LLM provider adapter.                                                                                               | Requirements require local-only mode and no mandatory hosted AI.                                                                | Privacy/cost risk and vendor lock-in.                                                      | Run AI routing tests with hosted AI disabled.                                                   | No for core platform; yes for DeepSeek-specific features.            |
| A-014 | Nous Hermes local serving can be implemented through vLLM, Ollama, or llama.cpp adapters.                                                                      | Preferred stack lists those local serving options.                                                                              | Adapter interfaces may need route-specific parameters.                                     | Verify selected runtime in environment config during EP-004/EP-008.                             | No.                                                                  |
| A-015 | RTK/Rust Token Killer integration is optional until licensing allows it.                                                                                       | Requirements explicitly require license review before use/fork/modify.                                                          | Copyleft or distribution obligations could block bundling.                                 | Complete legal/license ADR before adding RTK code or binary.                                    | Yes for RTK reuse; no for a clean-room token-compressor placeholder. |
| A-016 | UI must target WCAG 2.1/2.2 AA where practical.                                                                                                                | Accessibility requirements specify this.                                                                                        | UI tests and design components may be incomplete.                                          | Run accessibility acceptance tests and review components.                                       | No, but blocks production readiness for UI release.                  |
| A-017 | Telegram/mobile commands require account linking, scoped permissions, expiring approvals, 2FA for high-risk actions, and audit logs.                           | Security requirements specify these controls.                                                                                   | Unauthorized action risk.                                                                  | Review Telegram MCP/API tests and audit logs.                                                   | Yes for enabling Telegram high-risk actions.                         |
| A-018 | No production deployment or irreversible migration may be performed by a coding agent without explicit permission.                                             | STOP conditions require this.                                                                                                   | Data loss or unapproved live impact.                                                       | Check deployment target and command being run.                                                  | Yes for production deployment/migration.                             |
| A-019 | The blueprint pack itself does not contain application runtime code.                                                                                           | User requested a control-plane and implementation blueprint pack.                                                               | Coding agents must still implement repository through ExecPlans.                           | Inspect repository after applying this pack.                                                    | No.                                                                  |
| A-020 | Shell scripts may fail as placeholders until EP-001 creates matching package scripts.                                                                          | Greenfield repositories lack package scripts initially; required scripts must fail clearly rather than silently pass.           | Early `verify` fails before foundation exists.                                             | Run `sh scripts/preflight.sh` then EP-001.                                                      | No.                                                                  |
